# 세이버 애니메이션 초안 생성기

Pillow가 설치된 Python 3 환경에서 저장소 루트를 기준으로 실행합니다.

```sh
python3 tools/animate-saber.py /path/to/saber.png --output /path/to/new-output
```

입력은 투명 배경의 실제 12×15 PNG여야 합니다. 입력을 축소하거나 다시 그리지 않습니다.
출력 폴더가 이미 존재하면 중단하므로 원본이나 기존 게임 리소스를 덮어쓰지 않습니다.

출력:
- `frame-00.png` ~ `frame-20.png`: 12×15 개별 프레임. 0번은 입력과 RGBA 픽셀이 같습니다.
- `saber-sheet.png`: 256×128 시트. 21칸을 x=12*n, y=15*t에 배치하고 7개 갑옷 줄에 반복합니다.
- `comparison-16x.png`: 각 번호 위쪽은 전사 원본, 아래쪽은 생성 결과. 최근접 16배 확대입니다.
- 대기/이동/공격/사망/상호작용/비행/읽기 GIF 7종: 관찰을 위해 단발 동작도 반복합니다.
- `motion-report.json`: 부위별 이동량, 영역 정의, 잘린 픽셀 수, 재생 순서.

## 방법 및 한계

전사 천 갑옷의 기본 자세와 각 프레임 사이를 작은 영역별 RGB/투명도 오차로 비교해
정수 이동량을 추정합니다. 그 이동량으로 세이버의 실제 픽셀 영역을 옮겨 실루엣을 바꿉니다.
머리는 회전 없이 통째로 이동하고, 원본 팔/몸통/치마/발 픽셀을 재사용합니다.
색을 새로 생성하지 않으며 원본 팔레트에 속하는지 검사합니다.

이는 자동 해부학 인식이나 관절 추적이 아닙니다. 기본 영역은 머리 y=0..6,
몸통 y=7..9, 치마 y=10..11, 발 y=12..14이며 양쪽 가장자리는 팔로 봅니다.
원본에서 머리나 치마가 해당 경계를 넘으면 `--regions regions.json`으로 경계를 조정해야 합니다.
JSON은 `motion-report.json`의 `regions` 객체와 같은 형식입니다. 영역은 겹치지 않고
12×15 전체를 덮어야 합니다. 잘못된 분할을 자동으로 올바르게 해석하지는 못합니다.

사망 시 전사는 해골로 변하지만, 세이버 디자인을 유지하기 위해 15/35/65/90/100도
회전한 쓰러짐으로 근사합니다. 12×15 안에 넣기 위한 최근접 축소가 있으므로 사망 프레임의
작은 장식 일부는 손실될 수 있습니다. 별도 읽기 소품이나 칼날은 새로 그리지 않습니다.
가려져 있던 부분을 추론해 새로 만들지 않으므로 동작에 따라 경계의 수동 보정이 필요합니다.

GIF는 10ms 단위 제약 때문에 공격 15fps를 70ms, 상호작용 8fps를 130ms로 근사합니다.
실제 게임 속도는 기존 Java 코드가 결정합니다. 동일한 연속 그림은 GIF 인코더가 합치되
표시 시간은 유지합니다.

## 검증 현황

실제 전사 기본 자세를 테스트 입력으로 실행해 시트의 147칸, 프레임 0 일치,
팔레트 보존, 이동 실루엣 변화, GIF 디코딩을 확인했습니다.
이 테스트는 세이버 디자인 보존을 검증한 것이 아닙니다. 첨부 PNG의 원본 파일을 확보한 뒤
부위 경계와 모든 동작을 시각적으로 확인해야 합니다. 생성 결과는 게임에 자동 적용하지 않습니다.
